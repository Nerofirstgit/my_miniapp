## 自动化连接恢复经验

连接问题本轮已恢复，以下保留排查证据供再次出现时参考，不需要在正常连接时重复操作。

1. 旧入口 `cli.bat islogin` 返回 `IDE service port disabled`。读取的状态位置是 `%LOCALAPPDATA%\微信开发者工具\User Data\<安装路径散列>\Default`；当前运行进程的 `--user-data-dir` 则是 `%APPDATA%\微信开发者工具`。这是已观察到的路径差异，尚未证明它是全部原因。
2. 新入口 `wechatide.cmd` 可列出编译、截图与页面自动化工具。调用 `check_wechatide_status` 自动发起 Codex 授权，但返回 `CONNECT_ERROR: wait WechatIDE authorization timeout`。用户确认未看到授权弹窗。此次调用未取得可用于继续查询的任务 ID。
3. 工具附带的安装诊断脚本在包含空格的 `C:\Program Files (x86)` 路径上报命令截断错误；直接用 PowerShell 的 `&` 和完整引号调用入口能够输出帮助。因此不能仅依据这次诊断判定需要重装。

用户已在自己的 PowerShell 窗口尝试以下正式授权命令，返回 `CONNECT_ERROR`、`wait WechatIDE authorization timeout`、`source: connect`、`reason: connect_failed`。因此目前不能将连接失败仅归因于代理会话，也无需在相同状态下重复执行同一命令：

```powershell
& 'C:\Program Files (x86)\Tencent\微信web开发者工具\wechatide.cmd' auth -c codex
```

本轮恢复过程：用户保存并完全退出；官方授权入口冷启动后返回 pending，但短命令结束后进程消失、返回的端口拒绝连接。随后保持启动会话运行，正式授权任务返回 success，后续状态、编译、截图和页面操作可用。代理启动时应留意宿主命令会话的生命周期；不要强制终止有未保存编辑的工具进程。

安装目录 `debug.log` 中另有 `archive.cc` 的 `FILE_ERROR_FAILED` 警告，应用日志还有插件清单 `not found`，均未证明与授权失败相关。没有修改安装目录文件或手工伪造端口、授权状态。恢复后执行以下检查已确认登录有效、版本一致：

```powershell
& 'C:\Program Files (x86)\Tencent\微信web开发者工具\wechatide.cmd' -c codex check_wechatide_status --skill-version 0.3.11
```

这里的 `0.3.11` 对应本次读取的工具内置 skill；升级工具后应重新读取实际版本。只有检查结果确认登录有效、版本可用后，才继续打开项目与自动化验收。
